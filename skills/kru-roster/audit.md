# audit — report roster drift

Read-only. Assert every point of the wiring map (`SKILL.md`) agrees across files, then report a table: **check → OK / DRIFT → fix**. Report only; hand fixes to `hire`/`retire`, or apply on the user's say-so.

`bash scripts/audit.sh` runs the assertions a grep settles (it is also a `scripts/verify.sh` step); start from its output, then read for the rest.

## Assertions
1. **Version** — `VERSION` equals `.cursor-plugin/plugin.json` `version` equals the `.cursor-plugin/marketplace.json` plugin entry's `version` equals the `ROSTER.md` `# Roster — vX.Y.Z` header.
2. **Full registration** — every `agents/*.md` has (a) a `ROSTER.md` *Current specialists* row, (b) a *Model tiers* entry, (c) a `${CURSOR_PLUGIN_ROOT}/references/routing.md` routing row **or** *Step 4* review wiring **or** a `ROSTER.md` row marked **user-invoked** (user-triggered — via a thin invoker skill or direct spawn; absent from `lead` by design) **or** a `ROSTER.md` row marked **hook-invoked** (fired by the plugin's `hooks/hooks.json`; absent from `lead` by design — assert its named hook scripts exist under `hooks/`), and (d) a `SOURCES.md` row **or** an explicit stack-agnostic note.
3. **No orphans** — every `ROSTER.md` specialists row and every `lead` routing row names a real `agents/*.md` file.
4. **Model agreement** — every seat pins an explicit **full ID** (`claude-opus-5-5` / `claude-sonnet-5-5` / `claude-haiku-5-5`, the last for high-frequency read-only rule-check seats — never omitted, never a floating `opus`/`sonnet`/`haiku` alias) and it matches its `ROSTER.md` *Model tiers* row.
5. **Shared-block integrity** — the assertions above are all *registration*; this one is the **prompt body**, where drift actually lands (a seat can be perfectly registered and still have lost a rule). Against `shared-blocks.md`:
   - every file-reading seat has `## Context hygiene (stay lean)`; every TS-writing seat has `## TypeScript (shared skill)` — exemptions are the text-producing seats named in Block A, and nothing else
   - every seat carrying `## TypeScript (shared skill)` also carries `## Comments (earn the line)`, immediately after it — the seats named in Block I, identical text on all of them (no tailored slot outside Block I's listed surface syntax, so any other divergence is drift — the case clause is `Terse, in the file's own voice`, never a lowercase-regardless rule). `grep -L 'Comments (earn the line)' $(grep -l 'TypeScript (shared skill)' agents/*.md)` must return nothing. Its **read side** is one bullet in `kru-code-reviewer` → *What to hunt* (`grep -c 'earn the line' agents/code-reviewer.md`), and `lead`'s inline path carries the same clause for the edits it makes itself (`grep -c 'comment bar' skills/kru-lead/SKILL.md`) — the block without both is a rule that binds only the seats a diff happens to route through. Third surface, checked by reading rather than by grep: `skills/kru-comment-fix/SKILL.md` restates the standard instead of pointing at it, so its *cut* classes and Block I's clauses name the same set — every class the skill cuts, the block states. A gap there is drift the user finds by hand, one `skills/kru-comment-fix/SKILL.md` pass at a time
   - every **behavior seat** has `## Test-first (shared skill)` — the seats named in Block D. Its exemptions are a **closed list with recorded reasons** (the UI component builders, `kru-sanity-builder`, `kru-vercel-perf-optimizer`, `kru-toolchain-engineer`, `kru-vercel-platform-engineer`, the reviewers, the four text seats): a seat exempt for a reason not written in Block D is drift, and so is a *new* code-writing seat that quietly landed in neither list
   - the **UI component builders** named in Block E carry its token-vocabulary bullet identically — it has no tailored slot, so any divergence between them is drift. A seat that **enumerates the token names** instead of reading them off the project's token file has cached a list that lives in the repo being built; that's drift too, and it goes stale silently
   - the six **network-boundary seats** named in Block K carry `## Validation and forms (the repo's libraries)` (`kru-cloudflare-builder`, `kru-hono-builder`: the schema-only heading) — one section whatever the library. A seat carrying a library's trap inline, or a per-library `(if the repo uses X)` section, is a cache of that library's skill and is drift.
   - the **framework builders** named in Block L carry its props-contract handback bullet inside `## The seam` — `grep -l 'grouping miss, handed back' agents/*.md` lists exactly those seats, each with both ⚠ clauses
   - the **UI component builders** named in Block M carry its root-spacing bullet inside `## The seam` — `grep -l 'fights every other' agents/*.md` lists exactly those seats
   - each block's **invariant clauses** are present verbatim — `grep -c "⚠" shared-blocks.md` for the marked ones rather than trusting a count in this sentence, and read each one you find. They are the clauses drift has actually dropped, so a shortened bullet is the drift, not a style choice
   - every **code-writing seat** has `## Scope — build the real path, not every path` — the seats named in Block F. Its two ⚠ clauses are the ones a shortened copy drops, and dropping them inverts the block: without `breadth, never rigor` it licenses cutting error handling, without the name-it-in-your-return escape hatch the seat decides alone and silently
   - every seat whose output **renders** has `## Build and return — no self-dispatch` — the seats named in Block G, with its exemptions recorded there. This block was peer-copied before it had a canonical home, so the seats hired without it are the likeliest find
   - every seat that writes **code or config** has `## Exhaust the {library|tool|platform|database} before you write around it`, immediately after its official-source section — the seats named in Block N. `grep -l 'before you write around it' agents/*.md` lists exactly those seats; the heading's noun is a tailored slot, so grep the tail. Its **read side** is one bullet in `kru-code-reviewer` → *What to hunt* (`grep -c 'Hand-rolled past what ships' agents/code-reviewer.md`)
   - every seat that writes **code or config** has `## The return pass`, immediately before `## Context hygiene (stay lean)` — the seats named in Block O, the same 28 as Block N. It has **no tailored slot**, so `grep -l 'The return pass' agents/*.md` must list exactly those 28 and every copy must be byte-identical; any divergence is drift. Its **read side** is one bullet in `kru-code-reviewer` → *What to hunt* (`grep -c 'Left across the slice' agents/code-reviewer.md`), and its **trace** is the `Return pass:` line the block requires — `grep -l 'Return pass: <what you re-read>' agents/*.md` must match the same seats. The trace is what the block's enforcement hangs on: `hooks/log-dispatch.sh` writes `block_o`/`return_pass` per dispatch and `kru-dispatch-auditor` class 5 files on the pair, so a seat carrying the block without the trace line is silently unauditable. Check Block A's bound in the same pass — `to confirm the edit landed` must be present wherever `Never re-read a file you just edited` is, or the hygiene bullet reads as a ban on this block's pass
   - every seat that writes **code or config into the working repo** carries `memory: local` in its frontmatter and `## Memory (this repo's facts)` immediately before `## The return pass` (before `## Context hygiene (stay lean)` on `kru-test-writer`) — the seats named in Block Q, Block O's 28 plus `kru-test-writer`. No tailored slot: `grep -l "## Memory (this repo's facts)" agents/*.md` and `grep -l '^memory: local' agents/*.md` must list the same 29, every copy byte-identical. Any other `memory:` value, or the key on a reviewer, is drift the block's exemptions name
   - every seat whose source chain **leads with an MCP or a plugin**, and every seat naming an `MCP ` tool in its own frontmatter, carries Block P's unreachable-source clause — `grep -l "A source you can't reach" agents/*.md` must match the block's list, and the only permitted variation is the server's name. Derive the list rather than reading it: `grep -l 'MCP ' agents/*.md` plus the seats whose official-source section leads with an MCP. A seat carrying its **own** fallback sentence beside the clause is the drift the block names — the clause replaces it
   - every seat writing code **into an existing tree** has `## Match the repo` — the seats named in Block H, each carrying the install clause (`installed with the repo's own package manager`) **inside** it rather than under a separate heading
   - every seat ends with exactly one return contract (`Return:` line **or** `## Output`/`## Handoff`), per Block C
   - every **review seat** has `## What you return` *in addition to* `## Output` — the review seats named in Block C.1 (`grep -c 'What you return' agents/*.md` rather than trusting a count here). Check the pair, not either alone: a seat carrying only `## Output` never learned the split, and one whose caps got folded *into* its `## Output` has quietly edited a skill template four of them are required to reproduce verbatim. The two recorded exceptions (`kru-architecture-reviewer` design-mode specs, `kru-ux-auditor`'s path map) are in Block C.1 — an uncapped return for any other reason is drift
   - every seat that could reach for a **contrast ratio** carries Block J's clause, **positive half first** — the seats named there. A copy that keeps only the prohibition has dropped the half that does the work
   - **every seat** has `## Design for what they'll actually do`, immediately before its first other `## ` section — Block R. `grep -L "## Design for what they'll actually do" agents/*.md` must return nothing. Its two slots are tailored, so check the invariant clauses rather than the whole paragraph, and read the actor slot: a generic *users and attackers* that names nothing this seat's output meets is drift the grep can't see. A copy that restates Block F's scope rule inside it is drift too — Block R grounds F, never repeats it
   - **`{…}` slots differing per seat is correct** — report only missing/altered invariants, never "converge the tailored text"

   Cheap check: extract each block across `agents/*.md`, cluster by exact text, and look at the small clusters. A single seat differing from a 9-file majority is drift; a 3-seat cluster hired in one commit is *cohort* drift and the likeliest thing to find.

6. **Countable claims in `ROSTER.md` prose** — every number a skill row asserts about its own files is re-derived, not trusted: corpus entry counts (`grep -c "^## " skills/<name>/reference/*.md`), `Detect:` tier breakdowns, group counts, verified-URL counts. These drift silently in the opposite direction from the version header — a release bumps `VERSION` and the prose keeps the old figure, so the row reads authoritative and is wrong. Re-count rather than reading the sentence: the last row to carry a stale count carried it across three releases and was still wrong when the skill was deleted.

7. **Context load** — the plugin's entry under **Customize** prints the component inventory and the **always-on** token cost the plugin adds to every session, whether or not a seat fires. That number is the budget a new skill spends against, and the only place it is measured. Report it with the delta since the last audit, and name the components at the top of the per-component `always-on` column when it grew: a description is what a skill charges on every turn, so an over-long one is drift the count check can't see. The inventory also cross-checks assertion 1 from the CLI's side — a seat the CLI doesn't list is one `.cursor-plugin/plugin.json` claims and the loader never loaded. What the count can't say is how that cost splits: Cursor's context usage report breaks tokens across the system prompt, tool definitions, rules and skills ([changelog](https://cursor.com/changelog/canvas-improvements)). No built-in lists unused skills or audits prompts written for older models. Those two reads stay a gap (`PORTING.md`).
8. **Floor** — README → *Requirements* names a minimum Cursor version, and it holds only while it covers the newest frontmatter key the seats actually use. Derive it, don't read it: collect the keys across `agents/*.md` and `skills/kru-*/SKILL.md` frontmatter, and the floor is the release that shipped the newest one (`skills/kru-update/reviewed.md` records which release that is). A key below the floor is silently ignored on an older CLI rather than erroring, so the seat runs and the setting doesn't — drift with no symptom.

## Report
One row per failed assertion: which file(s), what disagrees, and the one-line fix (usually: run `hire`/`retire`, correct the version, or restore the clause from `shared-blocks.md`). If all pass, say so in one line. Do not edit files.
